Critical Correction #2: DUST Fee Delegation

✅ NEW FEATURE - Not in Original Guide

Midnight supports DUST fee delegation - a wallet with DUST can pay transaction fees for another wallet. This solves the chicken-and-egg problem of needing DUST to register for DUST.

How DUST Fee Delegation Works

  1. New Wallet Created: User has 0 DUST, cannot pay fees
  2. Funding Wallet (Alice): Pre-funded dev wallet with DUST
  3. Registration with Delegation: Alice pays DUST fees for new wallet's registration
  4. Result: New wallet is now registered and generating DUST

CLI Example (From Official Docs)

# Register for DUST with fee delegation
./midnight-node-toolkit generate-txs register-dust-address \
    --wallet-seed "NEW_WALLET_SEED" \
    --funding-seed "..01"  # Alice pays the DUST fees

# Parameters:
# --wallet-seed: The wallet being registered
# --funding-seed: The wallet paying DUST transaction fees

Implementation Impact

⚠️ NEW MESSAGE TYPE REQUIRED

Must add support for fee delegation parameter in registration transactions:

New Feature #3: Cardano Bridge for DUST Generation

✅ MAJOR FEATURE - Cardano Integration

Users can generate DUST from NIGHT holdings on Cardano blockchain, not just Midnight. This is a cross-chain feature using Plutus validators.

How Cardano → Midnight DUST Works

  1. User has NIGHT on Cardano: Holding NIGHT tokens on Cardano mainnet
  2. Connect CIP-30 Wallet: Connect Cardano wallet (Nami, Eternl, Lace, etc.)
  3. Designate Midnight Address: Map Cardano wallet → Midnight DUST address (recorded on-chain via Plutus validator)
  4. DUST Generation: NIGHT on Cardano generates DUST on Midnight
  5. Cross-Chain Sync: DUST balance updates automatically

Implementation Implications

Component Requirement Priority
Cardano Wallet Connection Integrate CIP-30 (window.cardano API) HIGH (for mainnet)
Address Mapping UI Designate/re-designate/de-designate Cardano ↔ Midnight mapping HIGH
Cross-Chain Balance Display Show NIGHT on Cardano + DUST on Midnight in unified view MEDIUM
Plutus Validator Integration Submit mapping transactions to Cardano HIGH
DUST Prediction Model Calculate DUST generation from Cardano NIGHT (cap & decay) MEDIUM
⚠️ RECOMMENDATION

Add Cardano Bridge feature as Phase 11 (after base Midnight implementation). This is a complex cross-chain integration that should not block MVP.

MVP Strategy: Focus on DUST generation from Midnight-native NIGHT first, add Cardano bridge in Phase 2.

New Feature #4: Midnight Native Tokens (MNTs)

✅ ASSET TYPE - Like Cardano Native Assets

Midnight supports custom ledger-defined tokens (MNTs) similar to Cardano Native Assets. Wallet must detect and display these tokens.

MNT Characteristics

  • Ledger-Defined: Created via smart contracts (Compact language)
  • Two Types: Unshielded MNTs (public) and Shielded MNTs (private)
  • Automatic Display: Wallet must detect MNTs from on-chain metadata
  • Transfer Rules: Handled by Midnight ledger (no smart contract needed)

Implementation Requirements
